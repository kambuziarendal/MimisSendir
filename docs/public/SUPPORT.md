Maintainer/publisher: **Kambuzi EDB**. Use [GitHub Issues](https://github.com/kambuziarendal/MimisSendir/issues) for ordinary bugs and [private security advisories](https://github.com/kambuziarendal/MimisSendir/security/advisories/new) for vulnerabilities. Upstream maintainers are not responsible for this fork.

For a bug, include client version, Haiku revision/architecture, package checksum,
bridge/server versions if relevant, a minimal reproduction, expected/actual behavior
and whether it also happens in an isolated account. Redact JIDs, phone numbers,
message text, media URLs, sticker keys, credentials and QR codes. Prefer synthetic screenshots.

Separate client rendering bugs from bridge/service bugs. The bridge version matters
even when the client version is unchanged. Do not relink or wipe data to reproduce a report.

Contributions should explain their purpose, preserve upstream notices, contain no
private deployment defaults, and include targeted verification. Native UI changes
need real Haiku interaction and installed-artifact identification; Linux unit tests
are not a substitute. Bridge changes need offline tests and controlled integration
with dedicated test accounts before release. Never use a maintainer's production
credentials or conversations in a test fixture.

Do not promise a support SLA, a hosted Signal service or all-XMPP compatibility in
catalog copy. Security reports follow SECURITY-PRIVACY.md, not public issues.
